# 私有化核心代码方案（当前仓库私有 + 新建公开壳仓库）

---

## 方案概述

| 仓库 | 内容 | 可见性 |
|------|------|--------|
| `blue-idea/collection`（当前） | 全部源码、CI/CD、构建、发布 Release | **私有** |
| `blue-idea/linkit`（新建） | 仅 README、Homebrew Tap 指向、下载链接 | **公开** |

Homebrew 的 `brew install blue-idea/tap/linkit` 指向的是 Release 二进制，与源码仓库是否公开无关，只需保证 Release 资产可公开访问即可。

---

## 实施步骤

### 第一步：将当前仓库设为私有

GitHub → `blue-idea/collection` → Settings → Danger Zone → **Change repository visibility → Private**

> Release 资产在仓库私有后默认仍可公开访问，`brew install` 不受影响。

### 第二步：新建公开仓库 `blue-idea/linkit`

内容只需包含：
- `README.md` — 产品介绍、截图、安装说明
- 指向 `blue-idea/collection/releases` 的下载链接

```bash
git clone git@github.com:blue-idea/linkit.git
# 将当前 README.md、ui/screenshot/ 复制过来即可
```

### 第三步：确认 Homebrew Tap 指向不变

检查 `homebrew-tap/Casks/linkit.rb`，确保 `url` 指向的是 `blue-idea/collection` 的 Release 资产：

```ruby
url "https://github.com/blue-idea/collection/releases/download/#{version}/Linkit.dmg"
```

私有仓库的 Release 资产 URL 对外公开可访问，Homebrew 下载不需要任何 token，**无需修改**。

### 第四步：GitHub Actions 无需改动

所有 CI/CD、构建、发布 workflow 仍在私有的 `blue-idea/collection` 中运行，权限和逻辑完全不变。

---

## 对比旧方案（Submodule）

| | Submodule 方案 | 本方案 |
|---|---|---|
| 复杂度 | 高（需维护两个仓库同步） | 低（一个仓库私有即可） |
| Actions 改动 | 需修改 3 个 workflow | **无需改动** |
| 历史清除 | 需要 `git filter-repo` 重写 | **无需操作** |
| brew install | 不受影响 | 不受影响 |

---

## 注意事项

1. 仓库私有后，外部 contributor 的 fork / PR 将无法访问，需提前告知
2. 如果 `blue-idea/tap` 仓库中的 workflow 使用了 `github.token` 拉取 `collection` 仓库内容，需换成有私有仓库权限的 PAT（但当前 Tap 只读 Release 资产，无此问题）
3. 新公开仓库 `blue-idea/linkit` 仅作展示用，不参与构建
